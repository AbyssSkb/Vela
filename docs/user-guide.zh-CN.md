# Vela 使用指南

[English](user-guide.md) · [项目首页](../README.zh-CN.md)

## 下载安装

在发布页选一个带版本号的版本，下载适合你设备的安装包。每个版本都列出安装包、安装说明和 SHA-256 校验文件。 [下载 Vela](https://github.com/AbyssSkb/Vela/releases)

| 平台 | 安装方法 |
| --- | --- |
| Android | 打开 ARM64 APK，按系统提示安装。如果要从调试签名版本换到公开版，请先保存收到的文件，再卸载旧版。卸载可能清除应用内的设备身份、配对和接收记录。 |
| macOS | 打开适合 Apple 芯片或 Intel 芯片的 DMG，把 Vela 拷到可写的「应用程序」文件夹。首次打开时按发布说明处理系统提示。 |
| Windows | 运行 x64 安装程序，为当前用户安装 Vela。 |
| Linux | 将 x64 AppImage 设为可执行，并放在可写位置。Vela 使用桌面环境的 Secret Service 钥匙环保护设备身份。启用登录启动后，将 AppImage 留在原处。 |

安装包工作流也提供保留七天的开发预览包。预览包关闭应用更新，Android 预览包使用调试签名。 [开发预览包](https://github.com/AbyssSkb/Vela/actions/workflows/build.yml)

## 配对设备

1. 在两台设备上打开 Vela。在其中一台选择「设备码」。
2. 在另一台选择「添加设备」，输入设备码，也可以在 Android 上扫码。然后点「连接」。
3. 通过可信渠道核对发起方的设备码，然后在出示设备码的一端确认请求。

窄屏打开时显示设备列表，宽高充足的窗口打开时显示关系图。你可以通过工具栏切换视图，也可以在本机为设备设置别名。移除设备会撤销本机对它的信任并关闭相关连接。对方开启在线监测时，可以在重新连接后得知这项变化。

从使用旧配对协议的版本升级后，需要重新配对。升级会保留设备身份、已接收的文件和接收记录。

## 发送内容

可以在 Vela 里发，也可以在 Android 或 macOS 的系统分享菜单里选 Vela，或在桌面端把文件拖入应用。

在 Android 上，还可以从文件的「打开方式」菜单或选中文字后的操作菜单中选择「Vela」，再选目标设备。文档提供方为虚拟文件提供导出格式时，Vela 可以发送导出的文件。发送文件夹请使用 Vela 内的「文件夹」。

在 Android 10 或更新版本上，系统分享菜单可能会推荐已配对的 Vela 设备。点设备快捷入口即可留在当前应用发送，并通过系统通知查看进度。点分享菜单里的 Vela 可以选择目标设备。后台发送不可用时，Vela 会打开以便继续。

| 要发什么 | 选什么 |
| --- | --- |
| 一个或一批文件 | 「文件」。每批最多 100 个。 |
| 文件夹 | 「文件夹」。Vela 会打包，接收后可手动还原。 |
| 消息或链接 | 「文字」。从设备选择返回时，已输入的内容会保留。 |
| 剪贴板里的内容 | 「剪贴板」。支持文字、图片或一个文件。 |
| Android 上的照片或视频 | 「相册」。在系统照片选择器中选择。 |

发送前核对目标设备。设备重名时，Vela 会显示设备码以便区分。设备选择页也会显示连接状态。发送一批文件或剪贴板内容时，可以点「查看待发送内容」核对。

Vela 一次处理一项传输。在 Vela 内可以查看进度或取消。发送结果会在屏幕底部短暂显示。失败时可以用原内容重试、换一台设备，或放弃这次发送。

## 接收与查找

接收端默认逐次确认。在「设置 → 接收」可以开启自动接收。

- **文件与链接。** 打开「接收记录」查找收到的内容。文件默认放在下载目录，保存位置可以在设置中修改。需要把文件粘贴到其他应用时，可在记录中选择「复制文件」。
- **剪贴板。** 接受剪贴板分享后，收到的内容会替换本机剪贴板。自动接收时也是如此。内容可在「接收记录」中找到。手动输入并发送的文字会保存在接收记录里，剪贴板保持原样。
- **文件夹。** 在收到的 `.vela-folder.zip` 记录中选择「还原文件夹」。归档最多包含 16 GiB 未压缩内容、10,000 个条目和 64 层目录，文件夹内应使用普通文件和目录。
- **删除记录。** 可以在「接收记录」或搜索结果里选择要删除的条目。删除时可以保留文件，也可以一并删除。

## 后台接收

后台接收默认开启。在「设置 → 接收」中查看本机状态和对应的系统设置入口。

| 平台 | 怎样保持可接收 |
| --- | --- |
| Android | 在「设置 → 通知」管理通知，在「设置 → 后台接收」查看电池优化状态。可以通过通知接收或拒绝请求。重启后首次解锁，已开启的接收服务会尝试恢复。 |
| macOS | 关闭窗口后，Vela 会留在菜单栏。「设置 → 接收 → 后台接收」让 Mac 在窗口关闭后保持唤醒和可接收。在「设置 → 通知」开启后，Vela 可以通过系统通知提醒接收请求。合盖和手动睡眠仍会中断连接。macOS 13 起可在设置首页开启「登录时启动」。 |
| Windows 和 Linux | 后台接收开启且托盘可用时，关闭窗口后 Vela 会留在系统托盘。可从托盘菜单打开或退出。托盘不可用时请保持窗口打开。系统睡眠或退出登录会停止接收。 |

**ColorOS** 在 Vela 的应用详情中查看「耗电管理」，开启后台运行和自启动。**澎湃 OS** 检查 Vela 的「后台自启动」和应用省电设置里的「无限制」。**One UI** 检查「从不自动休眠的应用」列表。菜单名称和位置随系统版本变化。 [ColorOS 设置示例](https://consumer.huawei.com/cn/support/content/zh-cn15848664/) · [澎湃 OS 自启动](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1624) · [澎湃 OS 电池设置](https://www.mi.com/global/support/faq/details/KA-538010/) · [三星应用管理](https://developer.samsung.com/mobile/app-management.html)

「后台接收」里的「自启动设置」会打开 Android 的相关系统设置。验证重启后能否接收时，请先重启并解锁手机，再从已配对设备发一个文件，最后打开 Vela 查看结果。

支持实时更新的 Android 系统可能在状态栏胶囊中显示传输进度。保持后台可用会增加耗电。强制停止 Vela 后，重新打开应用以恢复接收。 [Android 后台接收细节](background-execution-research.zh-CN.md)

桌面端通过菜单栏或托盘图标显示传输中和传输完成。在 macOS，点菜单栏图标即可查看状态、接收或拒绝请求。在 Windows 和 Linux，点托盘图标或接收请求通知可打开 Vela 进行确认。要在内容保存后自动打开窗口，可以开启「设置 → 接收 → 接收完成后显示窗口」，默认关闭。

## 更新 Vela

支持更新的发行版本会在后台检查更新。要手动检查或安装，打开「设置 → 关于 Vela → 应用更新」。有更新时，先完成正在进行的传输、配对或文件夹操作，再确认安装。

Vela 会验证更新签名和安装包，然后交给系统安装。Android 安装时按系统提示授权和确认。Linux 的 AppImage 如果在只读位置，请先移到可写目录。

## 连接与本机数据

两端的 Vela 都要运行并且可以连接。同网、跨网用相同的发送步骤。Vela 会在能直连时直连，需要时使用中继。两条路径上的流量都在设备之间加密。Vela 默认使用 Iroh 的公共发现和中继服务。在「设置 → 故障排查」中启用自定义中继后，如果列表里有地址，就会用该列表替换默认中继列表。

配对信息、应用设置和接收记录保存在本机。设备身份密钥和中继凭据保存在系统安全存储中。

## 故障排查

| 问题 | 怎么处理 |
| --- | --- |
| Vela 无法启动 | 在错误页重试，或打开「诊断」。 |
| 无法配对 | 在两台设备上打开 Vela，确认版本一致，并在出示设备码的一端确认请求。 |
| 设备暂时无法连接 | 检查另一端的 Vela 是否运行、两端能否联网，再刷新设备状态。使用自定义中继时，可以在设置中测试中继。 |
| 后台收不到请求 | 查看这台设备的「接收」设置。Android 检查通知和电池限制，macOS 检查菜单栏和睡眠状态，Windows/Linux 检查托盘和睡眠状态。 |
| 找不到收到的文件，或无法粘贴 | 打开「接收记录」，查看保存位置并尝试打开文件。不同应用接受的剪贴板类型可能不同。 |
| 文件夹归档被拒绝 | 检查解压后的内容大小、条目数、目录层数和符号链接。 |
| 更新无法安装 | Android 检查安装应用的授权，Linux 检查 AppImage 位置是否可写，再从「关于 Vela」重试。 |

反馈时附上两端的应用版本、机型、系统、网络、发送方向和复现步骤。从日志和截图里去掉设备码、凭据和私人内容。 [反馈问题](../CONTRIBUTING.zh-CN.md#反馈问题)
